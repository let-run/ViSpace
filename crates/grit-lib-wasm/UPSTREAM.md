Vendored runtime sources from gitbutlerapp/grit revision `974e2801c06bfe2b6ae0982467f9666b94a878b9` (MIT). Both desktop and browser use this local fork so bundle validation shares the same disk-backed core. Browser builds disable networking. Browser compatibility changes are recorded in `../../patches/grit-wasm.patch`.

`browser_repository::stream` accepts file metadata and a random-access IO adapter, not file payload arrays. It reads loose and indexed packed objects on demand, reconstructs OFS/REF deltas through streaming readers, hashes working files in 64 KiB chunks, and stages loose objects, snapshots and bundles in an append-only journal. Bundle checksums are incremental. The browser supplies immutable File snapshots and OPFS synchronous worker IO; desktop relay validation supplies file-backed IO. Metadata budgets bound file counts, index sizes and graph walks. No network feature or native process is used by browser repository operations.

The original small in-memory adapter remains for compatibility tests. App workers use the streaming adapter. `index::Index::serialize_into` is available outside tests, and internal tree validation is visible within this crate for canonical Git metadata serialization.
